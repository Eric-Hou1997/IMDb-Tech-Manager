## 1. 恢复后的目标

**v5.0 是各自 v4.1.0 的换栈版本：功能不增加、不减少，前端界面和操作行为保持一致；只更改技术栈并适配约定的三大系统。** 技术栈为 Rust + Tauri 2 + TypeScript + Vue 3/Vite，每产品五个构建目标。两产品独立，原数据与业务安全规则保留。

- 前端必须是 Vue/TypeScript 新实现；布局、CSS、图片、字体、间距、控件顺序、设置、弹窗、状态、文案及交互按各自 v4.1.0 对照。不能交付验证工作台或近似重设计，也不能只运行旧前端来冒充迁移。
- 后端复用当前已经实现的新核心，补齐缺失接线和真实差异；最终产品运行不依赖原 Go/Python/PowerShell 业务引擎。保留旧源码、资源和测试基线，不重新从零实现已有合格模块。
- ITM 保留 IMDb 规格、NFO Inspector/编辑、规则和 AI 标签、任务/自动运行、缓存、备份撤销及原更新能力。原权限、数据归属和 AI 记账规则不减配。
- TCM 保留只读 NFO 索引、Emby 卡片、原目录/维护/诊断/语言/手动更新。没有 AI；不增加 TCM 应用内自动安装更新或新的产品设置。
- 兼容真实 v4.1.0 用户数据，不能以归档了原字节代替新版可以使用；不为未正式发布的内部验证格式无限叠加兼容层。
- 原有八语言、原生菜单、登录启动、最小化/关闭/退出行为属于原功能迁移。平台 API 的必要差异单列，不成为改版理由。

依据：原始用户消息、两产品 `00-scope.md`/`scope.json` 的平台与技术栈约定、`11-handoff-2026-09-12.md` 的原版界面要求，以及当前接手指令。旧步骤、旧交接和旧功能组中的冲突表述保留作历史证据，不作为当前执行授权。

## 3. 已查明的偏差与纠正

第 9–12 步的高消耗不能仅用“多平台本来就难”解释。主要问题是阶段划分和验收顺序失真：前四步没有整体关闭，第 5–8 步仍有实际业务未接通，第 12 步清单却继续承接这些遗留；与此同时原界面尚未完成，验证工作台及其测试持续增长，后来又需要撤掉额外产品入口、恢复原版交互。步骤编号不能表明工作量或接近完成。

直接证据见 [前四步状态](04-status.md)、[第 5–8 步历史快照](07-implementation.md)、[旧第 9–12 步清单](10-completion-checklist.md) 和两产品 `15-baseline-only-correction.md`。纠偏记录明确列出新增设置、独立历史/迁移面板，以及 TCM 额外多选和分页的移除；这些是已经发生的返工。后续长记录反复报告没有真实 Tauri IPC 的预览，只能提供布局证据，不能关闭原生产品流程。

权限、NFO 安全、原数据可用、故障恢复和真实多平台差异属于必要迁移。已有核心和隔离验证有复用价值，不因产品 UI 偏差一并作废。现有证据没有按任务分摊的额度账单，不能声称浪费了某个百分比，也不能核实 v1.0–v4.1.0 与本次的精确额度比值。

| 偏差 | 处理原则 |
| --- | --- |
| 验证工作台变成产品 UI，新增设置和面板 | 以原版对应入口为准；已纠正部分保留，剩余差异逐项消除 |

执行顺序固定为完整 TCM → 完整 ITM → 五目标系统验收 → 发行准备；18 包最终验收另等授权。P1–P4 仅标交付归属，不恢复原 12 步，不重做已有实现。每个工作项必须写清原入口、当前差异、修改范围、可见结果和结束条件；达到条件即关闭，不继续沿相邻模块扩展。

## 6. 防止再次扩张和反复消耗

### 只保留一套当前结论

- 本文件管理目标、顺序和预算；各项目 `features.json`、`entrypoints.json` 管原版去向；既有 `evidence/` 保存适用源码和验证结果。直接更新相关项，不再追加每轮流水账或复制同一结果到多个长文档。
- 随当前用户流程核对相应入口和 `UNCLASSIFIED` 条目；不把重新扫描、重分类整仓库变成开工前置任务。产品阶段关闭前，剩余未分类入口必须有明确去向或有证据的非产品项说明。
- 每项区分未实现/未接通、已实现待验收、已验收、缺少外部条件。现有 ITM 18/TCM 16 个静态功能组不是完成分母；不为凑百分比重新切分测试或功能。
- 必需工作仅包括原版行为及约定平台差异。额外设置/面板、通用框架、未来兼容层、无关整理均不进入开发；不能用“更稳定”“更产品化”自动扩大范围。保护旧源码、用户数据、密钥和有效测试，不再次大范围清理。

### 验证范围随实际修改

| 修改类型 | 本次应做的验证 | 何时结束 |
| --- | --- | --- |
| 文案、CSS、Vue 展示 | 对应原版 DOM/截图/操作、相关前端回归及类型检查 | 对应差异消失且相关检查取得结果；不触发无关 Rust 全量测试 |
| 服务状态、IPC、线程与持久化 | 最小失败复现、修复、相邻必要负面路径、真实原生结果及受影响平台编译 | 当前状态链闭合；不扩展为整模块重构 |
| 业务核心 | 对应新旧行为与安全回归、依赖调用链、受影响平台检查 | 原契约和相关回归通过；已有无关证据保留 |
| 平台专属代码 | 对应系统/架构编译和真实行为 | 明确本目标结论；metadata 只作编译证据，缺实机不循环用它代替 |

多个同范围修复先定向验证，在可见交付组关闭时运行一次相关完整套件。新修改、失败或缺失结果才触发必要重跑。中断和结果丢失不计通过；已验证源码未受影响的证据不自动全部失效。编译缓存保留，避免无理由反复清理和重建。

### 工作块和停工规则

- 每次只推进一个原版流程中的具体差异；开工写清结束条件，完成即展示结果，随后进入同产品下一项，不需要为已授权的常规步骤反复确认。
- 以 45 分钟或有效额度下降 2 个百分点中先达到者作为复盘点，立即报告可见结果、未闭合项和消耗；这不是完成承诺或强制停工线。需要继续同一问题时须说明得到的新证据与剩余具体动作，不能无限追加相邻工作。
- 连续两次尝试没有缩小问题或得到新证据，停止该项试错，记录最小复现和实际阻塞；继续不依赖它的已授权工作，不伪造通过。
- 有效额度剩余 10% 时保存当前状态、未收结果及进程信息并停止。额度自行恢复不代表恢复授权。阶段首尾读取额度；工具只给整数且额度为账户共享，差值是观测值，不冒充本任务精确账单。现在不承诺剩余额度足够做完整个迁移。
- 阶段汇报只回答：实际完成了哪些原操作、展示哪一处真实界面、还有哪些实现/平台缺口、额度如何变化。最终包仍单列 0/18，不据此描述开发进度。
