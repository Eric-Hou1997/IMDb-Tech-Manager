## 🎬 เกี่ยวกับโครงการ

**IMDb Tech Manager** เป็นโครงการที่มุ่งจัดการข้อมูลทางเทคนิคของงานสร้างภาพยนตร์และโทรทัศน์

</p>

โครงการนี้มุ่งเน้นการดึง จัดโครงสร้าง ปรับให้เป็นมาตรฐาน และนำ **ข้อมูลจำเพาะทางเทคนิคของ IMDb** ไปใช้ โดยเปลี่ยนข้อมูลการผลิตภาพยนตร์และโทรทัศน์ที่กระจัดกระจายให้เป็นเมทาดาทาที่จัดการ ค้นหา และแสดงในคลังสื่อส่วนบุคคลได้

ขอบเขตที่ให้ความสำคัญในปัจจุบัน ได้แก่:

* ข้อมูลจำเพาะทางเทคนิคของ IMDb
* การจัดการเมทาดาทา NFO
* การสร้างแท็กทางเทคนิค
* ข้อมูลกล้องและเลนส์
* รูปแบบการถ่ายทำด้วยฟิล์มและดิจิทัล
* รูปแบบการผลิตและการนำเสนอ
* การปรับเมทาดาทาทางเทคนิคให้เป็นมาตรฐาน
* การนำเสนอข้อมูลทางเทคนิคในคลังสื่อ
* การประมวลผลเชิงความหมายด้วย AI
* การพัฒนาด้วยความช่วยเหลือจาก Coding Agent

คลังสื่อส่วนใหญ่ให้ข้อมูลชื่อเรื่อง นักแสดง ปีที่เผยแพร่ ความละเอียด ตัวแปลงสัญญาณ และรูปแบบเสียงได้ดีอยู่แล้ว

แต่ข้อมูลอย่าง **ใช้กล้องและเลนส์ชนิดใด เกี่ยวข้องกับรูปแบบการถ่ายด้วยฟิล์มหรือดิจิทัลใด ใช้กระบวนการผลิตแบบใด และมาสเตอร์กับนำเสนอผลงานสุดท้ายอย่างไร** มักไม่ได้รับการเก็บรักษาและแสดงอย่างครบถ้วนเป็นโครงสร้าง

IMDb Tech Manager มีเป้าหมายนำข้อมูลเหล่านี้เข้าสู่กระบวนการทำงานของคลังสื่อส่วนบุคคล

## 🧩 สถาปัตยกรรมโครงการ

IMDb Tech Manager (ITM) และ [Tech Card Manager (TCM)](https://github.com/Eric-Hou1997/Tech-Card-Manager) ทำงานร่วมกันในกระบวนการ **ข้อมูลจำเพาะทางเทคนิค** เดียวกัน

เครื่องมือทั้งสองรับผิดชอบคนละขั้นตอน:

* **ITM** รับผิดชอบการดึง ประมวลผล ตรวจสอบ และบำรุงรักษาข้อมูลจำเพาะทางเทคนิคกับเมทาดาทาที่เกี่ยวข้อง
* **TCM** นำข้อมูลจำเพาะที่ประมวลผลแล้วไปใช้ในคลังสื่อ เช่น สร้างการ์ดข้อมูลจำเพาะที่สอดคล้องกันในหน้าจอ Emby และรับผิดชอบการนำเสนอกับการผสานรวม

ITM และ TCM เป็นเครื่องมืออิสระที่ออกแบบให้ทำงานร่วมกัน แต่สามารถใช้งานและพัฒนาแยกกันตามกระบวนการทำงานได้

### 📦 IMDb Tech Manager (ITM)

**IMDb Tech Manager (ITM)** รับผิดชอบการจัดการและประมวลผลข้อมูล Technical Specifications เป็นหลัก

ความรับผิดชอบประกอบด้วย:

* การดึงข้อมูลจำเพาะทางเทคนิคของ IMDb
* การจัดโครงสร้าง Technical Specifications
* การปรับข้อมูลจำเพาะทางเทคนิคให้เป็นมาตรฐาน
* การจัดการไฟล์ NFO
* การเขียน Technical Specifications ลงไฟล์ NFO
* การสร้างแท็กทางเทคนิค
* การประมวลผลเชิงความหมายด้วย AI
* แสดงตัวอย่าง / ทดลองทำงาน
* แก้ไขด้วยตนเอง
* ประมวลผลแบบกลุ่ม
* บำรุงรักษาเมทาดาทา

ITM เปลี่ยนข้อมูลจำเพาะดิบเป็นเมทาดาทาสื่อที่มั่นคง มีโครงสร้าง และบำรุงรักษาได้

จากนั้น **TCM** สามารถใช้ Technical Specifications ที่ ITM ประมวลผลเพื่อสร้าง แสดง และซิงค์การ์ดข้อมูลจำเพาะทางเทคนิคภายในคลังสื่อ

### 🖥️ [Tech Card Manager (TCM)](https://github.com/Eric-Hou1997/Tech-Card-Manager)

**Tech Card Manager (TCM)** รับผิดชอบการนำเสนอและผสานรวม Technical Specifications ในคลังสื่อเป็นหลัก

ความรับผิดชอบประกอบด้วย:

* อ่าน Technical Specifications ที่ ITM หรือแหล่งข้อมูลที่เข้ากันได้จัดเตรียมไว้
* สร้างและบำรุงรักษาการ์ดข้อมูลจำเพาะทางเทคนิค
* นำเสนอข้อมูลทางเทคนิค
* ซิงค์เมทาดาทา
* ผสานรวม Web UI
* จัดการความเข้ากันได้ของสื่อประเภทต่าง ๆ
* ผสานรวมกับกระบวนการเมทาดาทาของคลังสื่อ

TCM และ ITM ใช้โมเดลข้อมูล Technical Specifications เดียวกัน แต่เน้นความรับผิดชอบต่างกัน

ITM เน้นดึง จัดระเบียบ และบำรุงรักษาข้อมูลทางเทคนิค ส่วน TCM นำข้อมูลที่ประมวลผลแล้วไปใช้ในสภาพแวดล้อมคลังสื่อจริง

ทั้งสองร่วมกันสร้างกระบวนการทำงานที่สมบูรณ์ได้:

**IMDb → ITM → NFO / Technical Specifications → TCM → การแสดงผลในคลังสื่อ**

### 🧭 ความสัมพันธ์กับแพลตฟอร์ม

ความรับผิดชอบของ ITM และ TCM **ไม่ได้ผูกติดถาวรกับระบบปฏิบัติการหรือเซิร์ฟเวอร์สื่อใดโดยเฉพาะ**

การติดตั้งใช้งานที่มีอยู่หรือกำลังพัฒนาอยู่ในปัจจุบันคือ:

* **ITM**: แอปจัดการข้อมูล Technical Specifications ซึ่งปัจจุบันมุ่งเน้น **macOS**
* **TCM**: เครื่องมือจัดการการ์ด Technical Specifications และผสานรวมคลังสื่อ ซึ่งปัจจุบันมุ่งเน้น **Emby**

นี่เป็นเพียงการติดตั้งใช้งานในปัจจุบัน ไม่ได้หมายความว่าโครงการทั้งสองจะจำกัดอยู่แค่แพลตฟอร์มเหล่านี้

การขยายในอนาคตอาจรวมถึง:

* ระบบปฏิบัติการเพิ่มเติม
* เซิร์ฟเวอร์สื่อเพิ่มเติม
* วิธีปรับใช้เพิ่มเติม
* แอปพลิเคชันไคลเอนต์เพิ่มเติม
* แหล่งข้อมูล Technical Specifications ที่เข้ากันได้เพิ่มเติม

ITM และ TCM ยังคงเป็นอิสระจากกันในระดับสถาปัตยกรรม และสื่อสารผ่าน Technical Specifications กับเมทาดาทาสื่อที่เป็นมาตรฐาน จึงเปิดทางให้ขยายไปยังหลายแพลตฟอร์มและสภาพแวดล้อมคลังสื่อ

## 🧠 หลักการออกแบบ

หนึ่งในเป้าหมายหลักของการพัฒนา IMDb Tech Manager คือทำให้ระบบอัตโนมัติ **ควบคุมได้ ตรวจสอบได้ และกู้คืนได้**

ไม่ว่างานจะใช้กฎโลคัลแบบกำหนดผลแน่นอนหรือ AI เป้าหมายคือดูแลเมทาดาทาสื่อของผู้ใช้ให้เชื่อถือได้ ไม่ใช่เพียงเพิ่มระบบอัตโนมัติให้มากที่สุด

### 1. ให้ความสำคัญกับกฎแบบกำหนดผลแน่นอน

เมื่อแก้ปัญหาได้อย่างเชื่อถือได้ด้วยกฎที่ชัดเจน จะเลือกใช้ตรรกะโลคัลแบบกำหนดผลแน่นอน

ตัวอย่าง ได้แก่:

* การแมปรูปแบบที่รู้จัก
* การปรับข้อมูลจำเพาะทางเทคนิคให้เป็นมาตรฐาน
* กฎของแท็ก
* การแปลงโครงสร้างข้อมูล
* การอ่านและเขียน NFO
* การประมวลผลไฟล์
* การตรวจสอบข้อมูล
* การระบุความเป็นเจ้าของ

งานเหล่านี้มีอินพุตและเอาต์พุตที่ชัดเจน ทำให้ตรรกะแบบกำหนดผลแน่นอนทดสอบ ทำซ้ำ และยืนยันได้ง่ายกว่า

งานที่แก้ได้อย่างเชื่อถือได้ด้วยกฎจะไม่ถูกส่งให้ AI เพียงเพื่อให้ได้ใช้ AI

### 2. ใช้ AI กับความหมายที่กำกวม

AI ใช้เป็นหลักกับปัญหาเชิงความหมายที่กฎตายตัวครอบคลุมได้ยาก เช่น:

* คำอธิบายภาษาธรรมชาติที่ไม่สม่ำเสมอ
* ข้อมูลจำเพาะทางเทคนิคที่กำกวม
* การแยกความหมายที่ซับซ้อน
* การระบุความสัมพันธ์ระหว่างผู้ผลิต ซีรีส์ และรุ่น
* การปรับวิธีแสดงข้อมูลเดียวกันหลายแบบให้เป็นมาตรฐาน
* ข้อมูลทางเทคนิคที่ต้องตีความตามบริบท

AI เป็นหนึ่งในความสามารถของ IMDb Tech Manager

AI ช่วยเสริมส่วนที่กฎแบบกำหนดผลแน่นอนมีประสิทธิภาพน้อยกว่า โดยไม่แทนที่กระบวนการประมวลผลข้อมูลทั้งหมด

### 3. เปลี่ยนผู้ให้บริการ AI ได้

ชั้นโมเดลยังคงกำหนดค่าได้ เพื่อเชื่อมต่อบริการโมเดลต่าง ๆ ผ่านการตั้งค่า เช่น:

```text
ผู้ให้บริการ
URL ฐาน
คีย์ API
โมเดล
```

ผู้ใช้จึงเปลี่ยนบริการโมเดลตามปัจจัยต่อไปนี้ได้:

* ความสามารถของโมเดล
* ค่าใช้จ่าย API
* ความพร้อมใช้งาน
* ความเข้ากันได้ของ API
* สภาพแวดล้อมการปรับใช้
* ข้อกำหนดด้านความเป็นส่วนตัว

กระบวนการข้อมูลหลักไม่ผูกติดถาวรกับผู้ให้บริการ AI รายใด

### 4. แสดงตัวอย่างก่อนเขียน

เมื่อทำได้ การดำเนินการที่แก้ไขไฟล์ NFO หรือเมทาดาทาสื่อควรแสดงผลลัพธ์ที่ตรวจสอบได้ก่อนเขียนจริง

กระบวนการทั่วไป:

```text
แสดงตัวอย่าง / ทดลองทำงาน
        ↓
ตรวจทานการเปลี่ยนแปลง
        ↓
ดำเนินการ
        ↓
ตรวจสอบผลลัพธ์
```

สิ่งนี้สำคัญอย่างยิ่งสำหรับ:

* การแก้ไข NFO
* การเขียน Technical Specifications
* การสร้างแท็กทางเทคนิค
* การอัปเดตแท็กทางเทคนิค
* การดำเนินการแบบกลุ่ม
* การย้ายเมทาดาทา

สำหรับการดำเนินการแบบกลุ่ม การรู้ว่าจะเปลี่ยนอะไรสำคัญกว่าการเพิ่มความเร็วในการทำงานเพียงอย่างเดียว

### 5. เคารพข้อมูลที่ผู้ใช้ดูแล

IMDb Tech Manager แยกเมทาดาทาตามแหล่งที่มาและความเป็นเจ้าของ

กระบวนการอัตโนมัติแก้ไขได้เฉพาะข้อมูลที่แอประบุอย่างแน่ชัดว่าเป็นของตนเอง ห้ามใช้เพียงความคล้ายของข้อความเพื่อสันนิษฐานว่าแท็กเป็นของ IMDb Tech Manager

โดยเฉพาะข้อมูลต่อไปนี้:

* แท็กที่ผู้ใช้ดูแลด้วยตนเอง
* แท็กที่สร้างโดยเครื่องมือภายนอก
* ข้อมูลที่ดูแลโดยแอปอย่าง TMM
* ข้อมูลที่ไม่ทราบเจ้าของ

ต้องไม่ถูกงานเบื้องหลังลบ อ้างสิทธิ์ หรือเขียนทับโดยไม่แจ้งให้ทราบ

Generated Tech Tag ที่ผู้ใช้แก้ไขด้วยตนเองจะถือเป็นข้อมูลที่ผู้ใช้ดูแลและได้รับการปกป้อง

### 6. แยก Technical Specifications ออกจากแท็ก

โครงการถือว่า **Technical Specifications** เป็นชั้นข้อมูลข้อเท็จจริง และ **แท็ก** เป็นข้อมูลอนุพันธ์ที่สร้างจากชั้นข้อเท็จจริงนั้น

```text
Technical Specifications
        ↓
การปรับมาตรฐาน / การประมวลผลเชิงความหมาย
        ↓
แท็กทางเทคนิค
```

ดังนั้น:

* Spec Agent รับผิดชอบเฉพาะ Technical Specifications
* ตัวสร้างแท็กรับผิดชอบ Technical Tags
* การแก้ไข Technical Specifications ไม่ควรเริ่มรีเฟรช IMDb โดยปริยาย
* การสร้างแท็กใหม่ควรเป็นการดำเนินการที่เป็นอิสระและสังเกตได้

การแยกนี้ช่วยป้องกันขั้นตอนประมวลผลต่าง ๆ รบกวนกัน และทำให้สร้างแท็กใหม่หรือผสานเครื่องมือเพิ่มเติมในภายหลังได้ง่ายขึ้น

### 7. การเขียนต้องปลอดภัย

ไฟล์ NFO เป็นข้อมูลระยะยาวที่สำคัญของคลังสื่อ กระบวนการแก้ไขจึงควรลดความเสี่ยงจากการเขียนไม่ครบ การลบแท็กโดยไม่ตั้งใจ หรือไฟล์เสียหาย

โครงการยังคงเสริมความแข็งแกร่งด้าน:

* การตรวจสอบความถูกต้องของ XML
* สำรองข้อมูลก่อนแก้ไข
* ตรวจสอบสถานะไฟล์ต้นฉบับ
* การเขียนแบบอะตอมมิก
* ตรวจสอบความปลอดภัยของพาธ
* ตรวจสอบความเป็นเจ้าของแท็ก
* ตรวจจับความขัดแย้ง
* คงไฟล์ต้นฉบับไว้โดยไม่เปลี่ยนแปลงเมื่อเกิดข้อผิดพลาด
* ความสามารถในการกู้คืนและเลิกทำ

เมื่อระบบไม่สามารถตัดสินได้อย่างปลอดภัยว่าควรแก้ไขข้อมูลหรือไม่ ค่าเริ่มต้นคือข้ามการดำเนินการแทนการเสี่ยงเขียนอย่างไม่ปลอดภัย

### 8. พฤติกรรมเบื้องหลังต้องสังเกตและตรวจสอบได้

การดำเนินการเบื้องหลังที่สำคัญควรแสดงข้อมูลสถานะที่ชัดเจนเมื่อทำได้

ตัวอย่างเช่น:

* กำลังประมวลผลอะไร
* แก้ไขอะไรไปแล้ว
* ผลลัพธ์ใดมาจากกฎโลคัล
* ผลลัพธ์ใดมาจาก AI
* จำนวนครั้งที่เรียก API
* การใช้โทเค็น
* การพบข้อมูลในแคช
* ค่าใช้จ่ายโดยประมาณ
* ระยะปัจจุบันของงาน
* สถานะสำเร็จ / ล้มเหลว / ข้าม
* สาเหตุข้อผิดพลาด
* ชื่อเรื่องหรือไฟล์ NFO ที่ได้รับผลกระทบ

โครงการพยายามไม่ลดงานเบื้องหลังที่ซับซ้อนให้เหลือเพียงข้อความ “สำเร็จ” โดยไม่แสดงสิ่งที่เกิดขึ้นจริง

## 🤖 การพัฒนาด้วย Coding Agents

คลังสาธารณะของ IMDb Tech Manager มีไฟล์:

[**`AGENTS.md` →**](../../AGENTS.md)

ไฟล์นี้เป็นจุดเริ่มต้นบริบทสำคัญสำหรับ Coding Agents อย่าง Codex ในการทำความเข้าใจและแก้ไขโครงการ

ปัจจุบัน `AGENTS.md` ครอบคลุม:

* อัตลักษณ์คลังและขอบเขตซอร์ส
* ความรับผิดชอบปัจจุบันของผลิตภัณฑ์
* ข้อจำกัดด้านสถาปัตยกรรมซอฟต์แวร์
* กฎความปลอดภัย NFO
* กฎความเป็นเจ้าของแท็ก
* กฎการเรียก AI และการนับโทเค็น
* ข้อกำหนดการจัดการวงจรชีวิต
* ข้อกำหนดการทดสอบและตรวจสอบ
* ขอบเขตการเผยแพร่
* ข้อกำหนดลายเซ็น OTA
* ขอบเขตการรองรับแพลตฟอร์ม
* การเปลี่ยนแปลงที่ไม่ควรทำ
* การตรวจสอบที่ต้องทำก่อนเสร็จสิ้นการเปลี่ยนแปลง

หลัง Fork หรือ Clone คลัง นักพัฒนาสามารถให้ Coding Agent ที่รองรับ Repository Context อ่าน `AGENTS.md` ก่อนวิเคราะห์หรือแก้ไขโค้ด

กระบวนการที่แนะนำ:

```text
Fork / Clone
        ↓
Coding Agent อ่าน AGENTS.md
        ↓
อ่านซอร์สโค้ดและการทดสอบที่เกี่ยวข้อง
        ↓
เข้าใจความรับผิดชอบและขอบเขตของโมดูล
        ↓
วิเคราะห์เส้นทางการทำงานที่ได้รับผลกระทบ
        ↓
สร้างแผนการติดตั้งใช้งาน
        ↓
แก้ไขโค้ด
        ↓
เรียกใช้การทดสอบที่เกี่ยวข้อง
        ↓
ตรวจสอบพฤติกรรมจริง
        ↓
ส่ง Pull Request
```

IMDb Tech Manager มุ่งให้มากกว่าซอร์สโค้ดเพียงอย่างเดียว:

```text
ซอร์สโค้ด
    +
ความรู้ด้านสถาปัตยกรรม
    +
ข้อจำกัดการออกแบบ
    +
กฎการพัฒนา
    +
วิธีการทดสอบ
    +
บริบทของ Agent
```

สิ่งนี้ช่วยทั้งนักพัฒนาที่อ่านโค้ดโดยตรงและผู้ที่ทำงานร่วมกับ Coding Agents อย่าง Codex ให้เข้าใจโครงการได้เร็วขึ้น พร้อมลดความเสี่ยงของการเปลี่ยนแปลงที่ทำงานได้ทางเทคนิคแต่ขัดต่อข้อจำกัดการออกแบบเดิม

## ⚠️ ข้อสงวนสิทธิ์

IMDb Tech Manager เป็นโครงการโอเพนซอร์สที่พัฒนาขึ้นโดยอิสระ

โครงการนี้ **ไม่มีความเกี่ยวข้องอย่างเป็นทางการ ไม่ได้รับอนุญาต หรือรับรองโดย IMDb, Emby หรือแพลตฟอร์มบุคคลที่สามอื่นใด**

ชื่อ เครื่องหมายการค้า ข้อมูล และบริการของบุคคลที่สามทั้งหมดยังคงเป็นทรัพย์สินของเจ้าของแต่ละราย

IMDb Tech Manager ให้เครื่องมือสำหรับการดึงและประมวลผลข้อมูลจำเพาะทางเทคนิค และการจัดการเมทาดาทาสื่อ

ผู้ใช้มีหน้าที่ตรวจสอบว่าการใช้ข้อมูล API เว็บไซต์ และบริการของบุคคลที่สามเป็นไปตามข้อกำหนดการให้บริการ ข้อกำหนดสิทธิ์ใช้งาน และกฎหมายที่เกี่ยวข้อง

## 💡 ความคิดเห็นและข้อเสนอแนะ

IMDb Tech Manager ยังคงพัฒนาอย่างต่อเนื่อง

หากคุณมีแนวคิดเกี่ยวกับ:

* ข้อมูลจำเพาะทางเทคนิคของ IMDb
* การปรับข้อมูลจำเพาะทางเทคนิคให้เป็นมาตรฐาน
* ข้อมูลกล้องและเลนส์
* รูปแบบการถ่ายด้วยฟิล์มและดิจิทัล
* การจัดการเมทาดาทา NFO
* กฎแท็กทางเทคนิค
* การประมวลผลเชิงความหมายด้วย AI
* UI / UX
* การทำงานร่วมกันระหว่าง ITM และ TCM
* การรองรับระบบปฏิบัติการเพิ่มเติม
* กระบวนการพัฒนาด้วย Coding Agent

ยินดีให้เข้าร่วมผ่าน Discussions หรือ Issues

โครงการจะพัฒนาฟีเจอร์ กฎข้อมูล และทิศทางการพัฒนาต่อไปตามความคิดเห็นจากการใช้งานจริง
