## 🎬 О проекте

**IMDb Tech Manager** — проект для управления технической информацией о кино- и телевизионных произведениях.

</p>

<img src="../images/poster.jpg" alt="Постер IMDb Tech Manager" width="700">

</div>

</p>

Проект получает, структурирует, нормализует и применяет **технические характеристики IMDb**, превращая разрозненную производственную информацию о фильмах и сериалах в метаданные, которыми можно управлять, выполнять поиск и отображать их в личных медиатеках.

Текущие направления работы:

* Технические характеристики IMDb
* Управление метаданными NFO
* Создание технических тегов
* Информация о камерах и объективах
* Форматы плёночной и цифровой съёмки
* Форматы производства и представления
* Нормализация технических метаданных
* Отображение технической информации в медиатеках
* Семантическая обработка с помощью ИИ
* Разработка с помощью Coding Agents

Большинство медиатек уже отлично отображает названия, актёрский состав, годы выпуска, разрешение, кодеки и форматы звука.

Однако сведения о том, **какие камеры и объективы применялись, какие форматы плёночной или цифровой съёмки использовались, какие производственные процессы выполнялись и как мастерилась и представлялась итоговая работа**, редко сохраняются и показываются полно и структурированно.

IMDb Tech Manager призван включить эти сведения в рабочий процесс личной медиатеки.

## 🧩 Архитектура проекта

IMDb Tech Manager (ITM) и [Tech Card Manager (TCM)](https://github.com/Eric-Hou1997/Tech-Card-Manager) совместно работают в едином процессе **Технических характеристик**.

Инструменты отвечают за разные этапы:

* **ITM** получает, обрабатывает, проверяет и поддерживает технические характеристики и связанные метаданные.
* **TCM** применяет обработанные характеристики в медиатеках — например, создаёт соответствующие карточки в интерфейсе Emby — и обеспечивает представление и интеграцию.

ITM и TCM — независимые инструменты, рассчитанные на совместную работу, но в зависимости от процесса их также можно использовать и разрабатывать независимо.

### 📦 IMDb Tech Manager (ITM)

**IMDb Tech Manager (ITM)** главным образом управляет данными Технических характеристик и обрабатывает их.

В его задачи входят:

* Получение технических характеристик IMDb
* Структурирование Технических характеристик
* Нормализация технических характеристик
* Управление файлами NFO
* Запись Технических характеристик в файлы NFO
* Создание технических тегов
* Семантическая обработка с помощью ИИ
* Предварительный просмотр / Пробный запуск
* Ручное исправление
* Пакетная обработка
* Обслуживание метаданных

ITM превращает необработанные технические характеристики в стабильные, структурированные и сопровождаемые медиаметаданные.

Обработанные ITM Технические характеристики затем может использовать **TCM** для создания, отображения и синхронизации карточек технических характеристик в медиатеках.

### 🖥️ [Tech Card Manager (TCM)](https://github.com/Eric-Hou1997/Tech-Card-Manager)

**Tech Card Manager (TCM)** главным образом отвечает за представление и интеграцию Технических характеристик в медиатеках.

В его задачи входят:

* Чтение Технических характеристик от ITM или других совместимых источников
* Создание и обслуживание карточек технических характеристик
* Представление технической информации
* Синхронизация метаданных
* Интеграция с веб-интерфейсом
* Обеспечение совместимости разных типов мультимедиа
* Интеграция с процессами метаданных медиатеки

TCM и ITM используют одну модель данных Технических характеристик, но решают разные задачи.

ITM получает, организует и поддерживает технические сведения, а TCM применяет обработанные данные в реальных средах медиатек.

Вместе они образуют полный процесс:

**IMDb → ITM → NFO / Технические характеристики → TCM → Представление в медиатеке**

### 🧭 Связь с платформами

Обязанности ITM и TCM **не привязаны навсегда к какой-либо операционной системе или медиасерверу**.

В настоящее время доступны или активно разрабатываются следующие реализации:

* **ITM**: приложение для управления данными Технических характеристик, сейчас ориентированное на **macOS**
* **TCM**: инструмент управления карточками Технических характеристик и интеграции с медиатекой, сейчас ориентированный на **Emby**

Это лишь текущие реализации; они не означают, что проекты останутся ограничены этими платформами.

В будущем могут появиться:

* Дополнительные операционные системы
* Дополнительные медиасерверы
* Дополнительные способы развёртывания
* Дополнительные клиентские приложения
* Дополнительные совместимые источники Технических характеристик

ITM и TCM сохраняют относительную архитектурную независимость и взаимодействуют через стандартизированные Технические характеристики и медиаметаданные, оставляя возможность дальнейшего развития на разных платформах и в разных средах медиатек.

## 🧠 Принципы проектирования

Одна из главных целей разработки IMDb Tech Manager — сделать автоматизацию **управляемой, проверяемой и восстанавливаемой**.

Независимо от того, использует задача детерминированные локальные правила или ИИ, цель — надёжное обслуживание медиаметаданных пользователя, а не простое увеличение степени автоматизации.

### 1. Предпочтение детерминированным правилам

Если задачу можно надёжно решить явными правилами, предпочтительна детерминированная локальная логика.

Примеры:

* Известные сопоставления форматов
* Нормализация технических характеристик
* Правила тегов
* Преобразования структур данных
* Чтение и запись NFO
* Обработка файлов
* Проверка данных
* Определение владельца

У этих задач чётко определены входные и выходные данные, поэтому детерминированную логику проще тестировать, воспроизводить и проверять.

Задачи, надёжно решаемые правилами, не передаются ИИ лишь ради использования ИИ.

### 2. ИИ для неоднозначной семантики

ИИ используется прежде всего для семантических задач, которые трудно полностью охватить фиксированными правилами, например:

* Нерегулярные описания на естественном языке
* Неоднозначные технические характеристики
* Сложное семантическое разложение
* Выявление связей между производителями, сериями и моделями
* Нормализация разных способов выражения одной информации
* Технические сведения, требующие контекстного толкования

ИИ — одна из возможностей IMDb Tech Manager.

Он дополняет области, где детерминированные правила менее эффективны, но не заменяет общий конвейер обработки данных.

### 3. Заменяемые поставщики ИИ

Уровень моделей остаётся настраиваемым и позволяет подключать разные сервисы моделей с помощью таких параметров:

```text
Поставщик
Базовый URL
Ключ API
Модель
```

Пользователь может менять сервис моделей с учётом:

* Возможностей модели
* Стоимости API
* Доступности
* Совместимости API
* Среды развёртывания
* Требований к конфиденциальности

Основной процесс обработки данных не привязан навсегда к конкретному поставщику ИИ.

### 4. Предварительный просмотр перед записью

Операции, изменяющие файлы NFO или медиаметаданные, по возможности должны показывать проверяемый результат до фактической записи.

Типичный процесс:

```text
Предпросмотр / Пробный запуск
        ↓
Проверка изменений
        ↓
Выполнение
        ↓
Проверка результата
```

Это особенно важно для:

* Изменений NFO
* Записи Технических характеристик
* Создания технических тегов
* Обновления технических тегов
* Пакетных операций
* Переноса метаданных

В пакетных операциях важнее знать, что именно изменится, чем просто увеличить скорость выполнения.

### 5. Уважение к данным пользователя

IMDb Tech Manager различает метаданные по источнику и владельцу.

Автоматические процессы могут изменять только данные, которые приложение достоверно определило как собственные. Одного сходства текста недостаточно, чтобы считать тег принадлежащим IMDb Tech Manager.

В частности:

* Теги, вручную поддерживаемые пользователями
* Теги, созданные внешними инструментами
* Данные, обслуживаемые приложениями вроде TMM
* Данные с неизвестным владельцем

не должны незаметно удаляться, присваиваться или перезаписываться фоновыми задачами.

Созданный технический тег, который пользователь изменил вручную, считается защищёнными данными пользователя.

### 6. Разделение Технических характеристик и тегов

Проект рассматривает **Технические характеристики** как слой фактических данных, а **Теги** — как производные сведения, созданные из этого слоя.

```text
Технические характеристики
        ↓
Нормализация / Семантическая обработка
        ↓
Технические теги
```

Следовательно:

* Spec Agent отвечает только за Технические характеристики
* Генераторы тегов отвечают за Технические теги
* Редактирование Технических характеристик не должно неявно запускать обновление IMDb
* Пересоздание тегов должно оставаться независимой и наблюдаемой операцией

Такое разделение предотвращает взаимное вмешательство этапов обработки и упрощает последующее пересоздание тегов или интеграцию дополнительных инструментов.

### 7. Безопасная запись

Файлы NFO — важные долговременные данные медиатеки, поэтому процессы изменения должны сводить к минимуму риск частичной записи, случайного удаления тегов или повреждения файлов.

Проект продолжает усиливать:

* Проверку корректности XML
* Резервное копирование перед изменением
* Проверку исходного состояния файла
* Атомарную запись
* Проверку безопасности путей
* Проверку владельца тегов
* Обнаружение конфликтов
* Сохранение исходного файла без изменений при сбое
* Возможности восстановления и отмены

Если система не может безопасно определить, следует ли менять данные, по умолчанию операция пропускается, чтобы исключить небезопасную запись.

### 8. Фоновое поведение должно быть наблюдаемым и проверяемым

Важные фоновые операции должны по возможности показывать понятные сведения о состоянии.

Например:

* Что обрабатывается
* Что изменено
* Какие результаты получены локальными правилами
* Какие результаты получены ИИ
* Количество вызовов API
* Использование токенов
* Попадания в кэш
* Оценочная стоимость
* Текущий этап задачи
* Состояния успеха / сбоя / пропуска
* Причины ошибок
* Затронутые названия или файлы NFO

Проект старается не сводить сложную фоновую работу к простому сообщению «успешно», не показывая, что произошло на самом деле.

## 🤖 Разработка с Coding Agents

Публичный репозиторий IMDb Tech Manager содержит:

[**`AGENTS.md` →**](../../AGENTS.md)

Это важная отправная точка контекста для Coding Agents, таких как Codex, при изучении и изменении проекта.

Сейчас `AGENTS.md` описывает:

* Идентичность репозитория и границы исходного кода
* Текущие обязанности продукта
* Архитектурные ограничения программы
* Правила безопасности NFO
* Правила владения тегами
* Правила вызовов ИИ и учёта токенов
* Требования к управлению жизненным циклом
* Требования к тестированию и проверке
* Границы выпуска
* Требования к подписи OTA
* Границы поддержки платформ
* Изменения, которые нельзя выполнять
* Проверки, необходимые перед завершением изменения

После создания форка или клонирования репозитория разработчики могут попросить Coding Agent с поддержкой контекста репозитория прочитать `AGENTS.md` до анализа или изменения кода.

Рекомендуемый процесс:

```text
Создать форк / Клонировать
        ↓
Coding Agent читает AGENTS.md
        ↓
Прочитать относящийся к задаче код и тесты
        ↓
Понять обязанности и границы модулей
        ↓
Проанализировать затронутые функциональные цепочки
        ↓
Составить план реализации
        ↓
Изменить код
        ↓
Запустить необходимые тесты
        ↓
Проверить фактическое поведение
        ↓
Отправить Pull Request
```

IMDb Tech Manager стремится предоставить больше, чем один исходный код:

```text
Исходный код
    +
Знание архитектуры
    +
Проектные ограничения
    +
Правила разработки
    +
Методы тестирования
    +
Контекст агента
```

Это помогает и разработчикам, читающим код напрямую, и разработчикам, работающим с Coding Agents вроде Codex, быстрее понять проект и снижает риск изменений, которые технически работают, но нарушают существующие проектные ограничения.

### Поддерживаемая платформа

В настоящее время поддерживается реализация для:

**macOS · Apple Silicon (arm64)**

Настольное приложение главным образом состоит из:

```text
Нативный загрузчик
      +
Ядро Go
      +
Локальный веб-интерфейс
      +
Движок Python
```

Репозиторий организован вокруг продукта, а не навсегда вокруг операционной системы.

Если в будущем появится поддержка Windows или других платформ, они останутся частью IMDb Tech Manager при сохранении тех же обязанностей продукта и процесса обработки данных.

### Текущий официальный релиз

Текущий публичный релиз:

**IMDb Tech Manager v4.1.0**

Релиз предоставляет приложение `.app` для Apple Silicon в ZIP-архиве вместе со следующими материалами:

* Журнал изменений релиза
* Данные проверки SHA-256
* Подпись OTA Ed25519
* Инструкции по установке

[**Открыть релизы →**](https://github.com/Eric-Hou1997/IMDb-Tech-Manager/releases)

Упрощённый китайский, традиционный китайский и английский (США) встроены. Французский, русский, японский, испанский и тайский предоставляются как проверенные языковые пакеты в соответствующем релизе приложения. Подробнее см. в [`docs/language-packs.md`](../language-packs.md).

Проект остаётся в активной разработке; его функции, архитектура, покрытие тестами и поддержка платформ будут развиваться.
