# Language packs

IMDb Tech Manager keeps `zh-CN`, `zh-Hant`, and `en-US` in the application. French, Russian, Japanese, Spanish and Thai remain external, presentation-only ZIP assets of the application GitHub Release.

For v5, `rewrite/src-tauri/core/assets/language_catalog.json` is the embedded release catalog. It binds each locale to one exact revision, release tag, asset name, SHA-256 digest and message-set hash. All five current descriptors select r2 assets from v5.0.0. The original `language-packs/catalog.json`, byte-identical `macos/language_catalog.json` and r1 sources remain unchanged as the v4.1.0 compatibility baseline. The client never searches backward through Releases or uses a separate language-pack update workflow.

The embedded catalog must match the running application version. The ZIP is verified before its bytes are atomically saved under a digest-bound preference in the v5 SQLite state. The application uses Tauri's platform app-data directory; it does not replace the old `~/Library/Application Support/IMDb Tech Manager/Language Packs/` files. Verified old directories are retained and imported through the existing migration transaction, and the pinned r1 catalog permits offline reuse of complete old packs.

At startup the application restores the configured external language and other previously installed locales to the exact current descriptors. Locales the user never downloaded are not fetched automatically. Failed downloads remain visible and retryable through the original language picker. Offline r1 compatibility is not proof that a new r2 download has succeeded.

Full original translations live at `language-packs/<locale>/r1/translations.json`. Necessary v5 task and platform additions are directly authored in `rewrite/language-packs/task-messages.json` and `platform-messages.json`. `rewrite/tools/build-language-packs.py` merges those presentation additions in memory and reuses the unchanged deterministic `tools/build-language-packs.py` recipe, complete message inventory and protected-token/script checks. It never edits r1 source or descriptors.

Run `python3 rewrite/tools/build-language-packs.py` to verify all five exact r2 descriptors and their full contents without emitting assets. After an intentional translation change, update the appropriate revision and release binding, regenerate its digest and message-set hash, and review the catalog. Never overwrite published revision bytes. Release collection emits the exact ZIP bytes verified against that catalog.

Language packs cannot alter NFO data, Technical Specs keys, ownership, Tag values, cache schemas, JSON protocols, prompts or model behavior. The default system prompt remains Chinese, and customized prompts retain their original bytes. A task captures its effective locale, pack revision and catalog hash at start; changing the UI language does not change that task's new logs, progress or errors. Old logs are never rewritten. Unknown underlying diagnostics retain their structured information.

The Web UI, native menu, dialogs and About/legal links use the same locale contract. The preserved v4 native launcher's user-default presentation cache belongs to the old implementation; v5 uses verified native strings from its loaded catalog-bound dictionaries. It is not an independent language selector or a data migration mechanism.

The archive digest authenticates the ZIP, and its authenticated manifest binds every `core`, `engine`, `native` and `web` section to its own SHA-256 digest. Missing, modified, wrong-product, wrong-release, wrong-revision, wrong-schema, incomplete or oversized content is rejected. A failed installation cannot replace a verified installed pack; recovery uses the exact catalog-bound asset. Source, fixture and asset verification remain separate from complete eight-language native operation and pixel acceptance, which the maintainer deferred for this release.
